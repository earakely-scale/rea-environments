## Pipeline (all under ~/capture/paperless on the VM)
1. `python3 seed.py init` (writes `.admin`), then `docker compose -p rea-paperless -f compose.yml up -d`; healthy within
   30 s (healthcheck `curl /accounts/login/`).
2. `python3 seed.py`: HTTP basic auth against `/api/` with `Accept: application/json; version=9` (no session, no CSRF),
   idempotent by name: 4 correspondents, 5 tags (one inbox tag), 3 document types, 2 storage paths, 3 custom fields
   (string, integer, monetary), 5 plain-text documents uploaded through `POST /api/documents/post_document/` (multipart,
   consumption polled through `/api/tasks/?task_id=`; text/plain needs no OCR, each took about 2 s), then patched with
   custom-field values; notes on 3 documents, 2 saved views (title filter, correspondent filter), 2 groups with
   permissions, 2 users, 1 IMAP mail account, 1 mail rule, 1 consumption workflow, and the application title through

3. `NODE_PATH=~/capture/node_modules node paperless/capture.mjs`: login through the allauth form at `/accounts/login/`

## Manifest facts
- 41 tools (GET 35, POST 3, DELETE 2, PATCH 1), 21 templated groups, every parameter from the built-in `numeric` rule
  (Paperless ids are integers). The opt-in rules (after-uid-literal, opaque-token, sibling-variance) matched nothing, so
  the no-rules manifest is identical in shape: 41 tools, the same 21 numeric parameters (confidence `inferred` in both
  views because the numeric rule is unconditional).
- 46 query-parameter names across tools, 16 distinct (acknowledged, correspondent__id, correspondent__id__in, fields,
  full_perms, id, is_root, last_correspondence, ordering, page, page_size, query, tags__id__all, task_name,
  title__icontains, truncate_content); 4 tools with a body shape (POST tags, PATCH tags/{id}, POST documents/{id}/notes,
  POST documents/selection_data); statuses 200/201/204/404; 0 excluded groups; coverage complete-within-view 41/41;
  unknowns authorization-model, response-semantics, state-transition; 9 limitations.
- Two DELETE tools: `DELETE /api/tags/{id}/` (204, empty, kept as an empty API reply) and
  `DELETE /api/documents/{id}/notes/?id=` (200 with the remaining notes as JSON).
- UI-only tools besides the scripted ones: ui_settings, tasks (`acknowledged=false`, `task_name=`), documents preview
  (text/plain bodies of the .txt documents), documents suggestions, `POST /api/documents/selection_data/`,
  `last_correspondence` and `full_perms` query variants. They are excluded from task generation, not from the manifest.
- The first record of `get_documents_by_id` is the UI's `?full_perms=true` read, so that task's question names the
  parameter.

## Surprises
- Paperless accepts HTTP basic auth on the whole API, so the seed never needed the login form or CSRF.
- Plain-text uploads are consumed in about 2 s each with no OCR; thumbnails are rendered as webp and are dropped by scoping.
- Page loads inside an Angular app multiply the shell's bootstrap calls; clicking sidebar links keeps the capture compact.
