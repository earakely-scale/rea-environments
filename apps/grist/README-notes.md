# Grist capture notes (rea showcase, batch 2)

- App: `gristlabs/grist:1.7.21` (grist-core **1.7.21**, from the server log "Grist version is 1.7.21"), digest
  `gristlabs/grist@sha256:4ef5b69ab411de298d2f70571fdcb9a0b00af0d7135d61255e641c5eef70f991`. Licence Apache-2.0 (grist-core
  `LICENSE.txt`). Compose project `rea-grist`, loopback-only `127.0.0.1:3220 -> 3220`. Storage is SQLite only: the home
  database `/persist/home.sqlite3` plus one `.grist` SQLite file per document, in a named volume; no second service.
- Configuration that mattered:
  - `GRIST_IN_SERVICE=true`: Grist 1.7 starts "not in service" and answers every `/api` call with 503 "Grist is not yet
    configured. Visit /boot to set up this installation." until an admin completes the interactive `/boot` setup. The env
    var skips that gate.
  - `PORT=3220` with the same port on both sides: Grist calls its own `APP_HOME_URL` from inside the container when a
    document or workspace is deleted. With the image's default 8484 inside and 3220 outside, `DELETE` failed with
    `ECONNREFUSED 127.0.0.1:3220` (500); matching ports fixed it.
  - Single user: `GRIST_DEFAULT_EMAIL=GRIST_ADMIN_EMAIL=rea-admin@example.test` with the built-in "minimal" login
    (`loginMiddlewareComment: no-logins`). Signing in just puts that user in the session; **there is no password** in this
    mode, so the only credentials are `GRIST_SESSION_SECRET` (generated by `up.sh`) and an API key the seed creates, both in
    `.admin` (mode 600, deleted at teardown). Loopback binding is the access control.
  - `GRIST_SANDBOX_FLAVOR=unsandboxed` (what the image picked anyway, logged as `flavor=unsandboxed`); formulas run in plain
    Python in the container. `GRIST_ALLOW_AUTOMATIC_VERSION_CHECKING=false`, `GRIST_TELEMETRY_LEVEL=off`.
- Tooling on the VM: rea 6.6.0, playwright-core 1.58.2, Chromium 155.0.8059.79 (snap, default temp profile worked),
  node v24.22.0, python 3.12.3, Docker 29.9.1, Compose 5.6.0.

## Manifest facts
- With rules: **31 tools** (GET 25, POST 3, PATCH 2, DELETE 1), 11 templated groups: `numeric` 7 (`orgs/{numeric}`,
  `.../access`, `.../usage`, `.../workspaces`, `workspaces/{numeric}`, `.../access`, `.../docs` POST) and
  `sibling-variance` 4 (`docs/{doc_id}`, `.../access`, `.../sql`, `.../tables`). 6 distinct query names (`filter`, `hidden`,
  `includeSupport`, `limit`, `q`, `sort`); 4 tools with a body shape; coverage `complete-within-view` 31/31; 0 excluded;
  unknowns authorization-model, response-semantics, state-transition.
- Without rules: 43 tools. `sibling-variance` merged the three documents' full ids **and** their 12-character url ids
  (the UI reads `docs/uSqDsYEz5xor`, the scripts `docs/uSqDsYEz5xornkGvKczKKC`) into one `{doc_id}` parameter.
- `opaque-token` did not fire on Grist's 22-character base62 document ids. Where a document id is followed by a table path
  that only one document has (`docs/<id>/tables/Keepers/records`), nothing varies, so those 15 tools stay literal and keep the
  id in their (60-character, truncated) names, e.g. `get_o_docs_docs_usqdsyez5xornkgvkczkkc_tables_keepers_record`. The
  scratch document's PATCH/DELETE are literal for the same reason. Table names (Keepers, Shifts, ...) under one document were
  not merged either.
- `exclude_tools` (`usage|attachments|access|profile_user|get_o_docs_orgs$|orgs_by_id$`) keeps tools whose first record
  only yields the admin's own name or email, the usage counters and the empty attachment list out of the task generator;
  with them in, six of twelve answers were "Rea Admin" or rea-admin@example.test. Two such answers remain
  (`workspace.owner.name`, `org.owner.name`).
