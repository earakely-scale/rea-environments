# Library of Congress JSON API (photos) capture notes (rea showcase, browser scenario capture)

- Public API at `https://www.loc.gov`, JSON through `fo=json` on the site's own URLs, attributes trimmed with `at=` and
  result counts with `c=`. No key, no login. Captured 2026-10-19 (UTC). Every item read individually is marked
  "No known restrictions on publication" or "on reproduction" in its `rights_advisory`; the catalogue metadata is a U.S.
  government work. The search listings return whatever LoC ranks first (the `lighthouse` listing starts with a Wittemann
  Collection print whose rights are "not evaluated"; it is only listed, not read on its own).
- This app replaces the assigned `nasa-images` (NASA Image and Video Library). Its capture and manifest worked (25
  transactions, 16 tools), but the retrieval-task generator found 0 candidates: NASA answers in Collection+JSON and every
  record field sits at `collection.items[i].data[0]`, deeper than the two levels the generator reads.
- Tooling on the VM: rea 6.7.0, Chromium 155.0.8059.79 (snap), node v24.22.0, python 3.12.3, agent-env 0.9.1334.

## Pipeline (all under ~/capture/loc-photos on the VM)
1. Research with single requests 1.2 s apart (about 35 in total): candidate items from collection searches, each item
   checked for status, size, rights statement and the forbidden word (one candidate listing, `/collections/`, contained it
   and was left out).
2. `scenario.json` (generated by a small helper from fixed URL lists): start at a `/photos/` search, then 27 `goto` reads,
   each followed by a 900 ms wait, and the 1.5 s settle wait. `rea capture-browser-scenario scenario.json --format json >
   loc-photos.capture.json`: 56 steps (start + 55 actions), 35.4 s, all `completed`; 29 transactions (28 navigations and
   one server redirect), all GET, statuses 200 x28 and 302 x1; 0 dropped events, no omissions; 817,776-byte Evidence.
3. `python3 ~/showcase/envbuild.py all loc-photos`.

## The scenario in prose
Start: `/photos/?q=lighthouse&fo=json&c=5&at=results,pagination`. Searches and listings: `/search/` for "covered bridge"
with the `original-format` facet (LoC answers 302 to `/photos/?q=covered+bridge...`, which the browser follows), `/search/`
for "glacier point" without a facet (200), the Photochrom Prints collection searched for "castle" and "glacier", the
Detroit Publishing Company collection for "bridge", Panoramic Photographs for "canyon", Stereograph Cards for "bridge",
the Historic American Buildings, Landscapes and Engineering Records collection for "covered bridge", and `/maps/` for
"grand canyon". Fifteen items by id with `at=item`: Corfe, Dover and Threave castles; the Rhone, Illecillewaet and Bossons
glaciers; Glacier Point and South Dome; the rustic bridge in Glenariff; High Bridge over the Kentucky River; the Natural
Bridge Hotel; Rascon Bridge; the Grand Canyon of Arizona, Fish Creek Canyon, the Grand Canyon of the Colorado; and the
Busching Covered Bridge survey record (`in0214`). Two items again with `at=resources` (their image files with pixel
width, height, size and MIME type) and one `/resource/ppmsc.08198/` record.

## Manifest facts
- 11 tools, all GET, with and without the opt-in rules (no opt-in rule matched). The numeric format rule templates the 14
  numeric item ids into `get_item_by_id` (`/item/{numeric}/`, 16 records including the two `at=resources` reads); the
  survey id `in0214` stays a literal tool `get_item_in0214`. Each collection is its own literal tool, as are `/photos/`,
  `/maps/`, `/search/` and `/resource/ppmsc.08198/` (named `get_resource_ppmsc`: the tool name drops everything after the
  dot of the id). Query parameter names: at, c, fa, fo, q. Nothing excluded. Unknowns: authorization-model,
  response-semantics, state-transition.
- The 302 is the first of `get_search`'s two records (the other is the "glacier point" search) and has an empty body;
  the task generator only reads a tool's first record, so `get_search` contributes no task.
- A first version of the scenario without the stereograph, survey, `/search/` and `/resource/` reads had only 6 tools and
  was refused by the manifest gate (8+).

## Visual facts in the JSON
Items carry `title`, `date`, `created_published`, `medium` ("1 photomechanical print : photochrom, color."), `summary`,
`subject_headings`, `location`, `notes`, `call_number` and `rights_advisory`; the `at=resources` responses list each image
file with its pixel width and height, byte size and MIME type, which is where the dimensions of a picture live.
