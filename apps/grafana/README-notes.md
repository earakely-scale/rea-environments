## Capture and scoping decisions
- Snap Chromium cannot use Playwright's default temp profile (confinement), so `capture.mjs` uses `launchPersistentContext`
  with a profile under `~/capture/grafana/profile` and `--no-sandbox`; `recordHar` works on the persistent context.
- The unscoped HAR was 119,358,184 bytes (embedded static assets); it was deleted on the VM after scoping.
- Default scoping (keep `^/api/|^/apis/`, default drop regex) kept 158 API records, over the 140 cap, because every page load
  repeats boilerplate: 4 plugin `settings` calls, the feature-flag `ofrep/v1/evaluate/flags` evaluation (43 KB each), user-storage
  and advisor calls. The scoped HAR therefore adds to the default drop regex: `^/api/plugins/|/ofrep/|/user-storage/|/advisor`
  (53 records: plugin settings 39, ofrep 9, user-storage 3, advisor 2). The per-page `preferences`, `user/orgs`, `user/stars`
  repeats (9 each) were kept as genuine API traffic.
- Exclusion tally for the 445 same-origin requests: 340 non-API paths (static, pages, avatars), 4 default auth patterns
  (`/api/login/ping`-style paths), 53 noise patterns, 0 other-origin, 0 non-JSON, 0 big-body, 0 over-max. Kept 105:
  GET 97, POST 5, PUT 1, DELETE 2; statuses 200 x103, 404 x2.
- Credential check on the VM before copy-back (occurrence counts in the scoped HAR): admin password 0, viewer password 0,
  `hf_[A-Za-z0-9]{8,}` 0, `ghp_` 0, `Bearer ` 0; no cookie headers; no `<scrubbed>` markers were needed (the seeding used curl,
  so no credential-bearing body is in the capture).

## rea results
- Capture: 105 records decoded, confidence `observed`, authority `historical-reference`, no `resource_constraint`.
- Manifest with rules: **48 tools** (GET 41, POST 4, DELETE 2, PUT 1), 11 templated tools / templated_groups 11,
  11 path parameters: `after-uid-literal` 5 (`/api/dashboards/uid/{uid}` GET and DELETE, `.../versions`,
  `/api/datasources/uid/{uid}`, `.../resources/scenarios`), `opaque-token` 2 (`/api/playlists/{uid}`, `.../items`),
  `numeric` 4 (default rule: `/api/teams/{numeric}`, `.../members`, `/api/users/{numeric}`, `.../teams`).
  32 distinct query parameter names (42 summed over tools). 0 excluded groups. 3 unknowns stated by the view:
  authorization-model, response-semantics, state-transition. Coverage `complete-within-view` (48/48). Confidence `inferred`.
- Manifest without rules: 50 tools, templated_groups 4 (numeric only). The three opt-in rules collapsed 9 literal tools
  (two dashboard uids + scratch-tide reads, versions, the datasource uid pair, the playlist uid pair) into 7 templated ones.
- `sibling-variance` contributed no parameter here: the folder siblings `/api/folders/general|lighthouse-rota|scratch-pier`
  and the `/apis/dashboard.grafana.app/v2/.../dashboards/{granite-ledger|blue-heron-kitchen}/dto` pair remained literal
  tools (`get_folders_lighthouse_rota`, `get_folders_scratch_pier`, `put_folders_scratch_pier`, `delete_folders_scratch_pier`,
  `get_dashboard_dashboards_*_dto`). A capture with more folder/dashboard siblings would be needed to see that rule fire.
- Tool names are rea's inferences from request lines; the manifest states no response semantics or state transitions.
